## 🖥️ [Slide 03] Legacy Systems Modernization & Core Support
### ศูนย์รวมโปรแกรมโรงพยาบาลยันฮี — การดูแลระบบจริงเกือบ 30 ระบบ (PHP)

![ศูนย์รวมโปรแกรมโรงพยาบาลยันฮี](/p1.png)
*ภาพหลักฐาน: ศูนย์รวมโปรแกรมของโรงพยาบาลยันฮี คอลัมน์ผู้พัฒนาที่มีชื่อ 'ทวีป โปราหา' คือระบบที่รับผิดชอบดูแลทั้งหมด*

### 📌 1. ระบบสำคัญที่รับผิดชอบพัฒนาและปรับปรุง:
1. **ระบบ HOIR (Hospital Incident Report):** รายงานอุบัติการณ์และความเสี่ยงของโรงพยาบาล *(จุดเด่น: มีทั้งระบบ BI วิเคราะห์ข้อมูล และคู่มือการดึงรายงานสำหรับผู้บริหาร)*
2. **ระบบตัวชี้วัด (KPI):** ติดตามและประเมินผลการดำเนินงานของแต่ละแผนกตามเกณฑ์มาตรฐานโรงพยาบาล
3. **ระบบ Mini CRM:** บริหารความสัมพันธ์และประสานงานข้อมูลคนไข้
4. **ระบบแผนฝึกอบรมและพัฒนาบุคลากรประจำปี:** สำรวจความต้องการและประวัติการอบรมบุคลากร
5. **ระบบเครื่องมือแพทย์เฉพาะทาง:** จองกล้อง DOM ในงานรักษารากฟัน, จองเครื่องมือรากฟันเทียม, ขัดหินปูน Airflow

### 🔄 2. วงจรการทำงานแบบครบวงจร 4 ขั้นตอน (End-to-End Delivery):
- 🤝 **1. ประชุมเก็บความต้องการ (Requirement Gathering):** เข้าประชุมกับ ผอ., ผู้จัดการฝ่าย, และหัวหน้าแผนกต่างๆ เพื่อรับฟังปัญหาและวิเคราะห์ความต้องการหน้างาน
- 💻 **2. พัฒนาและปรับปรุงระบบ (Development):** พัฒนาโค้ด PHP, ปรับจูนคำสั่ง SQL, ออกแบบหน้าจอให้ตอบโจทย์ และทดสอบความถูกต้อง
- 📚 **3. จัดทำคู่มือและอบรม (User Training & Manuals):** จัดทำคู่มือการใช้งานทั่วไป, คู่มือการดึงรายงาน พร้อมลงไปสอนเจ้าหน้าที่หน้างานด้วยตัวเอง
- 🛠️ **4. ดูแลและแก้ปัญหาต่อเนื่อง (User Support & Maintenance):** แก้ไขปัญหาบั๊ก ตอบคำถามหน้างาน และรักษาความเสถียรของระบบ 100%

> 🎙️ **บทบรรยายนำเสนอ:**  
> *"(ชี้ไปที่ภาพบนจอ) ภาพนี้คือหน้า 'ศูนย์รวมโปรแกรม' ของโรงพยาบาลยันฮีครับ ในคอลัมน์ผู้พัฒนาโปรแกรม ทุกระบบที่มีชื่อ 'ทวีป โปราหา' คือระบบที่ผมเป็นผู้รับผิดชอบดูแลทั้งหมดคนเดียวเกือบ 30 ระบบ ซึ่งเขียนด้วยภาษา PHP ครับ*  
> *สิ่งที่ผมอยากนำเสนอคือ ผมมีความพร้อมในการลุยงานระบบเดิม (Legacy Systems) แกะโค้ด แก้บั๊ก ปรับจูน SQL และเข้าประชุมกับ ผอ. และหัวหน้าแผนก เพื่อนำโจทย์มาพัฒนา จัดอบรมคู่มือ และ Support หน้างานอย่างใกล้ชิด ทำให้ผมทำงานร่วมกับบุคลากรทางการแพทย์ได้อย่างราบรื่นและเข้าใจหน้างานจริงครับ"*

## 🖥️ [Slide 04] Flagship System 1: IT Request (RequestTicker)
### ระบบบริหารจัดการใบแจ้งซ่อม & Workflow ของาน IT แบบ Paperless

* **สถานะโครงการ:** 🟢 **ขึ้น Production ใช้งานจริงแล้วในองค์กร (ลดการใช้กระดาษ 100%)**
* **เป้าหมาย:** เปลี่ยนกระบวนการแจ้งงานผ่านโทรศัพท์และกระดาษ สู่ระบบดิจิทัลที่ติดตาม SLA ได้แบบ Real-time
* **Workflow สถาปัตยกรรม:**
  1. แยกหมวดหมู่คำร้องชัดเจน: **งานบริการ**, **งานแก้ปัญหา**, และ **งานพัฒนา**
  2. คำร้องวิ่งตาม Approval Flow ของหัวหน้าแผนกก่อนส่งถึงทีม IT
  3. IT Admin คัดกรอง จ่ายงานให้ช่าง กำหนดวันเสร็จ (Due Date) และแตกงานย่อย (Sub-tasks) ได้
  4. ผู้แจ้งคำร้องเป็นผู้ตรวจรับงานและกดปิดงาน (User Acceptance) พร้อมให้คะแนนความพึงพอใจ
* **เทคโนโลยี:** `React + Vite + Tailwind CSS` | `FastAPI (Python) + PostgreSQL` | `Server-Sent Events + Telegram Bot`
* 🔗 **Source Code Repository:** [https://github.com/vick42uho/RequestTicker.git](https://github.com/vick42uho/RequestTicker.git)

> 🎙️ **บทบรรยายนำเสนอ:**  
> *"ระบบแรกคือ IT Request ครับ ตัวนี้ขึ้น Production ใช้งานจริงแล้ว ปัญหาเดิมของโรงพยาบาลคือ การแจ้งงานทางโทรศัพท์หรือกระดาษทำให้งานหลุดและตามสถานะยาก ผมจึงออกแบบระบบที่มี 3 หมวดชัดเจน คืองานบริการ งานแก้ปัญหา และงานพัฒนา มีการวิ่งตาม Flow อนุมัติของหัวหน้า ฝั่ง IT มี Admin คัดกรองและจ่ายงานให้ช่าง เมื่อช่างทำเสร็จ User จะเป็นคนตรวจรับและปิดงานครับ ช่วยให้กระบวนการเป็น Paperless 100% และงานไม่ตกหล่นครับ"*

## 🖥️ [Slide 05] Flagship System 2: Patient Media System
### ระบบคลังภาพถ่ายทางการแพทย์และหนังสือยินยอมตามมาตรฐาน PDPA

* **สถานะโครงการ:** 🟡 **พัฒนาเสร็จสมบูรณ์ (พร้อมสำหรับขั้นตอนการขึ้นระบบใช้งานจริง)**
* **เป้าหมาย:** พัฒนาขึ้นใหม่เพื่อทดแทนโปรแกรมคลังภาพเดิมของโรงพยาบาล ให้ยืดหยุ่น ปลอดภัย และเป็นไปตามกฎหมาย PDPA
* **ความสามารถระดับ Enterprise:**
  - จัดเก็บภาพถ่ายการรักษา (Before & After) แยกเป็นหมวดหมู่ตามคลินิกและหัตถการ ค้นหาด้วย HN
  - จัดเก็บเอกสารยินยอมของผู้ป่วย (Digital Consent Form) แนบติดกับชุดภาพถ่ายอย่างเป็นระบบ
  - ระบบประทับลายน้ำอัตโนมัติ (Dynamic Watermarking) ระบุผู้เข้าดูและเวลา เพื่อป้องกันภาพถ่ายหลุดออกภายนอก
  - ระบบควบคุมสิทธิ์เข้าถึงขั้นสูง (Fine-grained Access Control) และบันทึก Audit Log ทุกการเปิดดู
* **เทคโนโลยี:** `React + FastAPI (Python) + uv package manager + PostgreSQL`
* 🔗 **Source Code Repository:** [https://github.com/vick42uho/media.git](https://github.com/vick42uho/media.git)

> 🎙️ **บทบรรยายนำเสนอ:**  
> *"ระบบที่สองคือ Patient Media ครับ พัฒนาขึ้นมาเพื่อทดแทนโปรแกรมคลังภาพเดิมของโรงพยาบาลที่ไม่ยืดหยุ่น ตัวใหม่นี้ผมออกแบบให้จัดเก็บภาพ Before & After แยกตามคลินิก และที่สำคัญคือ มีระบบจัดเก็บหนังสือยินยอมของผู้ป่วย (Consent Form) ตามมาตรฐาน PDPA พร้อมระบบใส่ลายน้ำ (Watermarking) และจำกัดสิทธิ์การเข้าถึง เพื่อป้องกันการรั่วไหลของข้อมูลคนไข้ตามมาตรฐานความปลอดภัยข้อมูลสุขภาพครับ"*

## 🖥️ [Slide 06] Flagship System 3: Yanhee IAM Portal
### ระบบ Single Sign-On & Central Access Control (โจทย์ตรงจากท่าน ผอ.)

* **สถานะโครงการ:** 🟢 **สถาปัตยกรรมความปลอดภัยระดับ Core Enterprise**
* **โจทย์ความต้องการตรงจากท่าน ผอ. โรงพยาบาลยันฮี:**
  > *"ผอ. อยากได้ศูนย์รวมที่รวมทุกโปรแกรมในโรงพยาบาลไว้ที่เดียว ทำ Single Sign-On ล็อกอินครั้งเดียวแล้วเห็นเฉพาะโปรแกรมที่ตัวเองมีสิทธิ์ และเวลาโรงพยาบาลมีการปรับเปลี่ยนโครงสร้าง โยกย้าย ฝ่าย ส่วน แผนก บ่อยๆ สิทธิ์จะต้องอัปเดตอัตโนมัติ ไม่หลุดหรือตกค้าง"*
* **สถาปัตยกรรมระบบ:**
  - เชื่อมต่อยืนยันตัวตนผ่าน **Active Directory (LDAP)** ของโรงพยาบาล
  - ซิงค์ข้อมูลฝ่าย ส่วน แผนก และตำแหน่งงานจากฐานข้อมูล **Biosoft HR (MSSQL)** อัตโนมัติ
  - ออกแบบ **Dynamic RBAC (Role-Based Access Control)** คำนวณสิทธิ์ตามแผนกจริง หมดปัญหาสิทธิ์ค้างเก่า
  - ใช้สถาปัตยกรรม **Dual Token Rotation** (Short-lived Access Token + Refresh Token) พร้อม Token Blacklist สั่งตัดสิทธิ์ทันที
* **เทคโนโลยี:** `Next.js + Rust (Axum / Tokio Runtime) + PostgreSQL + MSSQL (Tiberius Driver)`
* 🔗 **Source Code Repository:** [https://github.com/vick42uho/yanhee_protal.git](https://github.com/vick42uho/yanhee_protal.git)

> 🎙️ **บทบรรยายนำเสนอ:**

## 🖥️ [Slide 07] Flagship System 4: Dynamic Icon Gate (Medical iFrame)
### ระบบแถบสถานะผู้ป่วยเชื่อมต่อ HIS แบบ Real-time (โจทย์ตรงจากท่าน รอง ผอ.)

* **สถานะโครงการ:** 🟢 **เชื่อมต่อกับระบบ HIS (Medhis) ของโรงพยาบาลโดยตรง**
* **โจทย์ความต้องการตรงจากท่าน รอง ผอ. โรงพยาบาลยันฮี:**
  > *"รอง ผอ. อยากได้แถบไอคอนแสดงสถานะคนไข้เพิ่มเติมจากระบบ Medhis เดิมที่มีอยู่ โดยให้ทาง Medhis เจาะช่องเป็น iFrame แนวนอนขนาดกะทัดรัดไว้ให้"*
* **สถาปัตยกรรมการประเมินผลและการเชื่อมต่อ:**
  - เชื่อมต่อ API ดึงข้อมูล Context ผู้ป่วยจากฐานข้อมูลของระบบ Medhis
  - พัฒนา **Rule Evaluation Engine ด้วยภาษา Rust** เพื่อประเมินเงื่อนไขการแสดงผลไอคอนแบบ Real-time:
    - คัดกรองช่วงอายุผู้ป่วย (0–15 ปี เด็ก, 16–25 ปี เด็กโต, 26–35 ปี ผู้ใหญ่)
    - ประเมินโรคประจำตัว, ประวัติการแพ้ยา และข้อควรระวังทางการแพทย์
  - 💡 **ความเชื่อมโยงกับระบบ AI:** สถาปัตยกรรมการดึง Context ผู้ป่วยแบบนี้ เป็นรากฐานเดียวกับการทำ **Feature Extraction & Data Pipeline** เพื่อป้อนข้อมูลเข้าสู่โมเดล AI ของโรงพยาบาล
* **เทคโนโลยี:** `Next.js + Rust (Axum) + PostgreSQL JSONB + Medhis HIS API`
* 🔗 **Source Code Repository:** [https://github.com/vick42uho/iFrame.git](https://github.com/vick42uho/iFrame.git)

> 🎙️ **บทบรรยายนำเสนอ:**  
> *"ระบบที่สี่คือ Dynamic Icon Gate ครับ ตัวนี้พัฒนาขึ้นตามโจทย์ตรงจากท่าน รอง ผอ. โรงพยาบาลยันฮีครับ ท่านอยากได้แถบไอคอนแสดงสถานะคนไข้แบบ Real-time เพิ่มเติมจากระบบ Medhis เดิม โดยให้ทาง Medhis เจาะช่อง iFrame ไว้ให้ ผมจึงสร้าง Rule Evaluation Engine ด้วยภาษา Rust เพื่อประเมินเงื่อนไข เช่น ช่วงอายุ และข้อควรระวังทางการแพทย์ แล้วดึงข้อมูลจาก Medhis มาแสดงผลทันที ซึ่งโครงสร้าง Data Pipeline แบบนี้เป็นรากฐานเดียวกับการเตรียมข้อมูลสำหรับโมเดล AI ในโรงพยาบาลครับ"*

## 🖥️ [Slide 08] Flagship System 5: TimeTrack OT
### แอปพลิเคชันคำนวณเวลาและโอทีบนมือถือ (Mobile Application)

* **สถานะโครงการ:** 🟢 **สถาปัตยกรรม 100% Offline-First บน Mobile Client**
* **จุดเด่นทางเทคนิค:**
  - คำนวณ OT กะเช้าและกะเย็นอัตโนมัติ พร้อม Live Preview แสดงจำนวนชั่วโมงและยอดเงินเรียลไทม์
  - ถ่ายภาพสลิปหรือหน้าจอเครื่องสแกนนิ้วแนบเป็นหลักฐานการลงเวลา จัดเก็บใน Sandboxed Storage ปลอดภัย
  - รองรับระบบปฏิทินไทย (พ.ศ. 2569) และระบบแนบใบรับรองแพทย์
  - ใช้งานได้ 100% แม้ไม่มีสัญญาณอินเทอร์เน็ต ด้วย **Expo SQLite (WAL Mode - Write-Ahead Logging)**
* **เทคโนโลยี:** `React Native 0.81 + Expo SDK 54 + SQLite (WAL Mode)`
