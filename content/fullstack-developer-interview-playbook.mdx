## 🎙️ ส่วนที่ 1: บทแนะนำตัวเปิดหัว (Opening Pitch)

> ⏱️ **เวลาที่ใช้:** ประมาณ 1.5 – 2 นาที  
> 🎭 **จังหวะพูด:** น้ำเสียงเป็นธรรมชาติ เป็นกันเอง มั่นใจ สุภาพ และสบตากรรมการทั้งสองท่าน

### 🗣️ บทพูดจริง:
"สวัสดีครับพี่ๆ ทั้งสองท่านครับ ผมชื่อ**วิค**นะครับ หรือชื่อจริง **ทวีป โปราหา** ครับ

ปัจจุบันผมเป็นโปรแกรมเมอร์ อยู่ที่**โรงพยาบาลยันฮี**ครับ งานหลักๆ ที่ผมทำอยู่ที่ยันฮีตอนนี้ จริงๆ จะแบ่งเป็น **2 พาร์ทใหญ่ๆ** ครับ

- **พาร์ทแรกคือ งานดูแลและปรับปรุงระบบเดิมของโรงพยาบาล** ซึ่งเป็นเว็บที่เขียนด้วยภาษา PHP ตอนนี้ผมดูแลอยู่คนเดียวเกือบ 30 โปรแกรมเลยครับ มีตั้งแต่ระบบ HOIR, KPI, Mini CRM ไปจนถึงระบบจองเครื่องมือแพทย์เฉพาะทาง
- **ส่วนพาร์ทที่สองคือ งานออกแบบและสร้างระบบใหม่ๆ** ตั้งแต่การคุย Requirement กับผู้บริหารระดับ ผอ. และ รอง ผอ., ออกแบบฐานข้อมูล, พัฒนาทั้ง Frontend และ Backend REST API ไปจนถึงการขึ้น Production ใช้งานจริงในโรงพยาบาลครับ"

## 🏛️ ส่วนที่ 2: พาร์ทแรก — งานดูแลและปรับปรุงระบบเดิม (Legacy PHP ~30 ระบบ)

> 💡 **เป้าหมายของพาร์ทนี้:** พิสูจน์ให้กรรมการเห็นว่า **"เราไม่มีอีโก้เรื่องเทคโนโลยี พร้อมลุยงานระบบเก่า แกะโค้ดแก้บั๊กได้ และคุยกับคนหน้างานรู้เรื่อง"**

![ศูนย์รวมโปรแกรมโรงพยาบาลยันฮี](/p1.png)

### 📌 ระบบหลักที่ได้เข้าไปพัฒนาและดูแล:
1. **ระบบ HOIR (Hospital Incident Report):** ระบบรายงานอุบัติการณ์และความเสี่ยงของโรงพยาบาล *(จุดเด่น: มีทั้งระบบ BI วิเคราะห์ข้อมูล และคู่มือการดึงรายงานสำหรับผู้บริหาร)*
2. **ระบบตัวชี้วัด (KPI):** ติดตามเป้าหมายการทำงานของแต่ละแผนก
3. **ระบบ Mini CRM:** บริหารจัดการข้อมูลและประสานงานลูกค้า
4. **ระบบแผนฝึกอบรมและพัฒนาบุคลากรประจำปี:** จัดการประวัติและสำรวจผู้เข้าอบรม

### 🔄 วงจรการทำงานแบบครบวงจร 4 ขั้นตอน (End-to-End):
- 🤝 **1. ประชุมเก็บความต้องการ (Requirement Gathering):** เข้าประชุมกับ ผอ., ผู้จัดการฝ่าย, และหัวหน้าแผนกต่างๆ เพื่อรับฟังปัญหาหน้างานและสิ่งที่ต้องการเพิ่ม
- 💻 **2. พัฒนาและปรับปรุงระบบ (Development):** เขียนโค้ด PHP, ปรับแก้ SQL Query, และเพิ่มฟังก์ชันให้สอดคล้องกับระเบียบปฏิบัติโรงพยาบาลที่เปลี่ยนไป
- 📚 **3. อบรมและจัดทำคู่มือ (User Training & Manuals):** จัดทำคู่มือการใช้งานทั่วไป, คู่มือการดึงรายงาน พร้อมลงไปสอนเจ้าหน้าที่หน้างานด้วยตัวเอง
- 🛠️ **4. ดูแลและแก้ปัญหาต่อเนื่อง (User Support):** แก้ไขบั๊ก ตอบคำถาม และดูแลความเสถียรของระบบให้ใช้งานได้ตลอดเวลา

## 🚀 ส่วนที่ 3: พาร์ทสอง — งานออกแบบและสร้างระบบใหม่ (Full-Stack & Systems)

> 💡 **เป้าหมายของพาร์ทนี้:** โชว์ทักษะ Full-Stack สมัยใหม่, ความไว้วางใจที่ได้รับจากผู้บริหารระดับสูง (ผอ. / รอง ผอ.), และการเชื่อมต่อกับระบบ HIS ของโรงพยาบาล  
> 🔗 **คลิกที่ลิงก์ GitHub เพื่อเปิดดู Source Code ในแท็บใหม่ได้ทันที:**

### 1️⃣ IT Request — ระบบแจ้งซ่อมและของาน IT แบบ Paperless
* **สถานะ:** 🟢 **ขึ้น Production ใช้งานจริงแล้ว** (ช่วยลดการใช้กระดาษและการโทรตามงาน 100%)
* **ที่มา & ปัญหา:** งานแจ้งซ่อมและของาน IT ในโรงพยาบาลเดิมทีกระจัดกระจาย ติดตามสถานะยาก
* **Flow การทำงาน:**
  1. แยกประเภทใบคำร้องชัดเจน: **งานบริการ**, **งานแก้ปัญหา**, และ **งานพัฒนา**
  2. ใบคำร้องวิ่งตาม Flow อนุมัติ (ผ่าน ผจก. หรือ ผอ.)
  3. ฝั่ง IT มี Admin คอยคัดกรองเบื้องต้น แล้วจ่ายงานให้ทีมที่รับผิดชอบ
  4. แท็กชื่อผู้รับผิดชอบ กำหนดวันเสร็จ (Due Date)
  5. เมื่อช่างทำงานเสร็จ User จะเป็นคนตรวจรับและกดปิดงาน
* **Tech Stack:** Frontend: `React + Vite + Tailwind CSS` | Backend: `FastAPI + PostgreSQL`
* 🔗 **Source Code:** [https://github.com/vick42uho/RequestTicker.git](https://github.com/vick42uho/RequestTicker.git)

### 2️⃣ Patient Media — ระบบคลังภาพถ่ายทางการแพทย์ตามมาตรฐาน PDPA
* **สถานะ:** 🟡 **พัฒนาเสร็จแล้ว** (อยู่ในขั้นตอนเตรียมพูดคุยสรุป Flow หน้างานเพื่อขึ้นระบบจริง)
* **ที่มา & ปัญหา:** พัฒนาขึ้นมาใหม่เพื่อทดแทน "โปรแกรมคลังภาพเดิม" ที่ฟังก์ชันไม่ยืดหยุ่นและยังไม่ตอบโจทย์
* **ฟังก์ชันสำคัญ:**
  - จัดเก็บภาพถ่ายการรักษา (Before & After) อย่างเป็นหมวดหมู่ตามคลินิก
  - จัดเก็บเอกสารยินยอมของผู้ป่วย (Consent Form) ตามมาตรฐาน PDPA
  - มีระบบประทับลายน้ำ (Watermarking) และควบคุมสิทธิ์เข้าถึงภาพเพื่อป้องกันข้อมูลรั่วไหล
* **Tech Stack:** `React + FastAPI + uv + PostgreSQL` *(ใช้ uv ช่วยจัดการ Environment และ Dependency ได้รวดเร็วระดับสูง)*
* 🔗 **Source Code:** [https://github.com/vick42uho/media.git](https://github.com/vick42uho/media.git)

### 3️⃣ Yanhee IAM Portal — ระบบ Central Access Control & Single Sign-On
* **สถานะ:** 🟢 **ระบบสถาปัตยกรรมความปลอดภัยระดับ Core Enterprise**
* **ที่มา (Requirement ตรงจากท่าน ผอ.):**  
  > *"ผอ. อยากได้ระบบศูนย์รวมที่รวมทุกโปรแกรมในโรงพยาบาลไว้ที่เดียว ทำ Single Sign-On ล็อกอินครั้งเดียว แล้วเห็นเฉพาะโปรแกรมที่ตัวเองมีสิทธิ์ และเวลารพ. มีการปรับเปลี่ยนโครงสร้าง โยกย้าย ฝ่าย ส่วน แผนก บ่อยๆ สิทธิ์จะต้องไม่หลุดหรือค้างเก่า"*
* **สถาปัตยกรรม & กลไก:**
  - เชื่อมต่อกับ **Active Directory (LDAP)** สำหรับการ Login ยืนยันตัวตน
  - ซิงค์ฐานข้อมูลบุคลากร **Biosoft (HR MSSQL)** เพื่อดึงรายชื่อ, ฝ่าย, แผนก, ตำแหน่ง มาอัปเดตอัตโนมัติ
  - คำนวณสิทธิ์ตาม **Dynamic RBAC (Role-Based Access Control)** ทำให้หมดปัญหาสิทธิ์ไม่ตรงกับโครงสร้างจริง
  - สถาปัตยกรรม **Dual Token Rotation** และมี Token Blacklist สำหรับสั่งตัดสิทธิ์ทันที
* **Tech Stack:** `Next.js + Rust (Axum / Tokio) + PostgreSQL + MSSQL (Tiberius)`
* 🔗 **Source Code:** [https://github.com/vick42uho/yanhee_protal.git](https://github.com/vick42uho/yanhee_protal.git)

### 4️⃣ Dynamic Icon Gate (Medical iFrame) — ระบบแถบไอคอนสถานะผู้ป่วย
* **สถานะ:** 🟢 **ระบบเชื่อมต่อกับ HIS (Medhis) โดยตรง**
* **ที่มา (Requirement ตรงจากท่าน รอง ผอ.):**  
  > *"รอง ผอ. อยากได้แถบไอคอนแสดงสถานะคนไข้เพิ่มเติมจากระบบ Medhis เดิมที่มีอยู่ โดยให้ทาง Medhis เจาะช่องเป็น iFrame แนวนอนเล็กๆ ไว้ให้"*
* **สถาปัตยกรรม & กลไก:**
  - สร้าง API เชื่อมต่อไปดึงข้อมูล Context ผู้ป่วยจากฐานข้อมูลของ Medhis
  - พัฒนา **Rule Evaluation Engine (ด้วยภาษา Rust)** เพื่อคำนวณเงื่อนไขการแสดงผลไอคอนแบบ Real-time เช่น:
    - ช่วงอายุ 0–15 ปี แสดงไอคอนเด็ก
    - ช่วงอายุ 16–25 ปี แสดงไอคอนเด็กโต
    - ช่วงอายุ 26–35 ปี แสดงไอคอนวัยรุ่น
    - ตรวจสอบโรคประจำตัวและข้อควรระวังทางการแพทย์
  - 💡 **ความเชื่อมโยงกับ AI:** โครงสร้างการคัดแยก Context คนไข้แบบนี้ เป็นรากฐานเดียวกับการทำ **Feature Extraction & Data Pipeline** เพื่อป้อนเข้าสู่โมเดล AI ในโรงพยาบาล
* **Tech Stack:** `Next.js + Rust (Axum) + PostgreSQL JSONB + Medhis API`
* 🔗 **Source Code:** [https://github.com/vick42uho/iFrame.git](https://github.com/vick42uho/iFrame.git)

### 5️⃣ TimeTrack OT — แอปพลิเคชันคำนวณเวลาและโอทีบนมือถือ
* **สถานะ:** 🟢 **Mobile Application (Offline-First Architecture)**
* **จุดเด่น:**
  - คำนวณ OT กะเช้าและกะเย็นอัตโนมัติ พร้อม Live Preview
  - ถ่ายภาพสลิปหรือหน้าจอเครื่องสแกนนิ้วแนบเป็นหลักฐานการลงเวลา เก็บใน Sandboxed Storage
  - รองรับปฏิทินไทย (พ.ศ. 2569) และระบบแนบใบรับรองแพทย์
  - ทำงานแบบ **100% Offline-First ด้วย Expo SQLite (WAL Mode)**
* **Tech Stack:** `React Native 0.81 + Expo SDK 54 + Expo SQLite (WAL)`
* 🔗 **Source Code:** [https://github.com/vick42uho/TimeTrackOT.git](https://github.com/vick42uho/TimeTrackOT.git)

## 🎯 ส่วนที่ 4: หมัดฮุกเชื่อมโยงสู่ รพ.จักษุ รัตนิน (The Winning Closer)

> 🗣️ **ประโยคสรุปปิดท้ายที่มัดใจทั้ง IT Manager และ Head of HR:**

"พอผมได้อ่านประกาศรับสมัครตำแหน่ง **Software Developer — Full-Stack (AI-Focused) ของ รพ.จักษุ รัตนิน** ที่มองหาคนที่เข้าใจทั้ง:
1. การพัฒนา REST API เชื่อมต่อกับระบบ HIS
2. การเชื่อมโยงกับระบบ LIS/PACS และเครื่องมือแพทย์
3. การทำ Data Pipeline สำหรับ AI Model และ BI Dashboard
4. การดูแลเรื่องความถูกต้องและความปลอดภัยของข้อมูลคนไข้ตามมาตรฐาน PDPA

ผมมั่นใจมากว่า **'ประสบการณ์ตรงที่ผมทำอยู่ที่ยันฮี ตอบโจทย์สิ่งที่พี่ๆ กำลังมองหาแบบ 100%'**

เพราะผมเคยเชื่อมต่อกับระบบ HIS (Medhis) มาแล้วจริง, เข้าใจโครงสร้างข้อมูลสุขภาพ, รู้วิธีการทำ Data Pipeline และระบบความปลอดภัย, และที่สำคัญคือ **ผมทำงานร่วมกับผู้บริหารระดับ ผอ. และบุคลากรหน้างานจริงได้อย่างราบรื่น**

วันนี้ผมเตรียมทั้งสไลด์และเปิด Source Code ในเครื่อง Laptop มาพร้อมให้พี่ๆ ตรวจสอบ อยากให้เจาะลึกระบบไหน หรือเปิดดูโค้ดตัวไหน บอกผมได้เลยครับ ขอบคุณครับ!"
