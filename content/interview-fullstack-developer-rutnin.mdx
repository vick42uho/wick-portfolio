## 🎙️ 1. การแนะนำตัว (Opening Pitch)

> **คำแนะนำ:** นั่งหลังตรง ยิ้มอย่างมั่นใจ สบตากรรมการทั้งสองท่าน พูดด้วยน้ำเสียงเป็นธรรมชาติแบบเพื่อนร่วมงาน

"สวัสดีครับพี่ๆ ทั้งสองท่านครับ ผมชื่อ**วิค**นะครับ หรือชื่อจริง **ทวีป โปราหา** ครับ

ปัจจุบันผมเป็นโปรแกรมเมอร์ อยู่ที่**โรงพยาบาลยันฮี**ครับ งานหลักๆ ที่ผมรับผิดชอบอยู่ที่ยันฮีตอนนี้ จริงๆ จะแบ่งออกเป็น **2 พาร์ทใหญ่ๆ** ครับ

* **พาร์ทแรกคือ งานดูแลและปรับปรุงระบบเดิมของโรงพยาบาล:** เป็นเว็บแอปพลิเคชันที่เขียนด้วยภาษา **PHP** ซึ่งตอนนี้ผมดูแลอยู่คนเดียวเกือบ 30 โปรแกรมเลยครับ ทั้ง Mini CRM, HOIR (ระบบรายงานอุบัติการณ์และความเสี่ยง), KPI และโปรแกรมอบรมบุคลากร
* **พาร์ทที่สองคือ งานออกแบบและสร้างระบบใหม่ (Full-Stack):** พัฒนาตั้งแต่การวิเคราะห์ Requirement, ออกแบบสถาปัตยกรรมฐานข้อมูล, ทำ REST API และหน้าบ้าน จนถึงการขึ้น Production ใช้งานจริงในโรงพยาบาล เช่น ระบบ IT Request, ระบบคลังภาพคนไข้ PDPA, ระบบ Central IAM ที่ได้รับโจทย์ตรงจากท่าน ผอ., และระบบ Dynamic Icon Gate ที่เชื่อมต่อกับระบบ Medhis (HIS) ตาม Requirement ของท่าน รอง ผอ. ครับ

พอผมเห็นประกาศรับสมัครของ **รพ.จักษุ รัตนิน** ตำแหน่ง Full-Stack ที่เน้นเรื่อง AI และการเชื่อมต่อระบบ HIS ผมรู้สึกทันทีว่าตรงกับสิ่งที่ผมทำอยู่ทุกวัน เพราะการทำ AI หรือ Dashboard ในโรงพยาบาล หัวใจสำคัญไม่ใช่แค่ตัวโมเดล แต่คือการทำ **Data Pipeline ดึงข้อมูลจากระบบ HIS มาคลีนให้ถูกต้องและปลอดภัย** ซึ่งผมคลุกคลีกับเรื่องนี้อยู่ตลอดครับ"

## 🏛️ 2. พาร์ทแรก: งานดูแลและปรับปรุงระบบเดิมของโรงพยาบาล (PHP)

ในโรงพยาบาลยันฮี ผมเป็นผู้รับผิดชอบดูแลระบบภายในที่เป็นเว็บภาษา **PHP** เกือบ 30 โปรแกรม โดยโปรแกรมหลักๆ ที่ผมได้เข้าไปปรับปรุง แก้ไข และเพิ่มฟังก์ชัน มีดังนี้:

| หมวดหมู่ระบบ | รายชื่อโปรแกรมตัวอย่าง | หน้าที่และความสำคัญ |
|---|---|---|
| **คุณภาพและความปลอดภัย** | **HOIR (Incident Report)**, **KPI**, ตรวจสอบเวชระเบียน | บันทึกอุบัติการณ์ความเสี่ยงและติดตามตัวชี้วัดคุณภาพสำหรับผู้บริหาร |
| **คลินิกและเครื่องมือเฉพาะทาง** | **จองกล้อง DOM ในงานรักษารากฟัน**, **จองเครื่องมือรากฟันเทียม**, ขัดหินปูน Airflow | จัดการคิวและจองเครื่องมือแพทย์เฉพาะทางที่มีความละเอียดอ่อนสูง |
| **บริการผู้ป่วยและสนับสนุน** | **Mini CRM**, **จองห้องพักสำหรับญาติ Vol.2**, คลังภาพ, ประวัติวัคซีน | อำนวยความสะดวกให้ผู้ป่วยและญาติที่เข้ารับการรักษาในโรงพยาบาล |
| **บริหารบุคลากร** | **ประเมิน Competency**, **แผนฝึกอบรมประจำปี**, Job Description | จัดการข้อมูลสมรรถนะและการพัฒนาบุคลากรทั้งโรงพยาบาล |

### กระบวนการทำงาน 4 ขั้นตอน (End-to-End Delivery)
1. **ประชุมเก็บความต้องการ (Requirement Gathering):** เข้าประชุมร่วมกับ **ผอ., ผู้จัดการฝ่าย, และหัวหน้าแผนกต่างๆ** ที่เกี่ยวข้อง เพื่อรับฟังปัญหาหน้างานจริงและระเบียบปฏิบัติที่เปลี่ยนไป
2. **พัฒนาและปรับปรุงระบบ (Development):** เขียน PHP ปรับแก้คำสั่ง SQL Query เพิ่มฟังก์ชันและหน้าจอให้ตรงกับความต้องการของหน้างาน
3. **อบรมและจัดทำคู่มือ (User Training):** จัดทำทั้งคู่มือการใช้งานทั่วไป และคู่มือการดึงรายงาน พร้อมลงไปสอนพี่ๆ เจ้าหน้าที่หน้างานด้วยตัวเอง
4. **ดูแลและแก้ปัญหาต่อเนื่อง (User Support):** แก้ไขบั๊ก ตอบข้อซักถาม และคอย Support ผู้ใช้งานตลอดการใช้งานจริง

### 1. ระบบ IT Request (ระบบแจ้งซ่อมและของาน IT แบบ Paperless)
* **โจทย์และปัญหาเดิม:** เดิมทีการแจ้งงานใช้กระดาษและโทรศัพท์ตามงาน ทำให้งานหลุด ไม่รู้ว่าใครรับผิดชอบ และติดตามสถานะไม่ได้
* **จุดเด่นของระบบ:**
  * แยกประเภทใบคำร้องชัดเจน 3 รูปแบบ: **งานบริการ (Service), งานปัญหา (Issue), และงานพัฒนาโปรแกรม (Development)**
  * **Workflow การอนุมัติ (Approval Chain):** ถ้าใบงานต้องการการอนุมัติ ระบบจะส่งให้ผู้จัดการส่วน หรือผู้อำนวยการฝ่ายหน้างานลงนามอนุมัติก่อนส่งเข้าแผนก IT
  * **IT Triage & Dispatch:** ฝั่ง IT มี Admin คอยคัดกรองเบื้องต้น แล้วจ่ายงานให้แผนกที่รับผิดชอบ แท็กชื่อผู้ปฏิบัติงาน และกำหนดวัน Deadline
  * เมื่อช่าง/เจ้าหน้าที่ทำงานเสร็จ User ผู้แจ้งจะเป็นผู้ตรวจรับและกดปิดงาน
* **Tech Stack:** Frontend: **Vite + React** | Backend: **FastAPI + PostgreSQL**
* **🔗 GitHub Repository:** [https://github.com/vick42uho/RequestTicker.git](https://github.com/vick42uho/RequestTicker.git)

### 2. ระบบ Patient Media (ระบบคลังภาพทางการแพทย์ & PDPA)
* **โจทย์และปัญหาเดิม:** พัฒนาขึ้นมาใหม่เพื่อทดแทน "โปรแกรมคลังภาพเดิม" ของโรงพยาบาลที่ยังไม่ตอบโจทย์การใช้งาน
* **จุดเด่นของระบบ:**
  * จัดเก็บภาพถ่ายการรักษา (Before & After) สำหรับคลินิกและแผนกต่างๆ อย่างเป็นหมวดหมู่
  * จัดการแบบฟอร์มการยินยอมของผู้ป่วย (Consent Management) ตามมาตรฐาน **PDPA**
  * มีระบบประทับลายน้ำและควบคุมสิทธิ์เพื่อป้องกันการรั่วไหลของภาพถ่ายทางการแพทย์
  * *สถานะปัจจุบัน:* พัฒนาเสร็จเรียบร้อยแล้ว อยู่ในขั้นตอนเตรียมพูดคุยสรุป Flow กับทีมหน้างานเพื่อเตรียมขึ้นใช้งานจริง
* **Tech Stack:** Frontend: **React** | Backend: **FastAPI + uv + PostgreSQL**
* **🔗 GitHub Repository:** [https://github.com/vick42uho/media.git](https://github.com/vick42uho/media.git)

### 3. ระบบ Central Access Control (Yanhee IAM Portal)
* **โจทย์จากผู้บริหาร:** **ได้รับ Requirement ตรงจากท่าน ผอ.** ต้องการระบบรวมศูนย์ที่รวมทุกโปรแกรมในโรงพยาบาลไว้ที่เดียว ทำ **Single Sign-On (SSO) ล็อกอินครั้งเดียว** จะเห็นเฉพาะโปรแกรมที่ตนเองมีสิทธิ์ตามหมวดหมู่ชัดเจน และต้องรองรับกรณีโรงพยาบาลมีการโยกย้าย ฝ่าย/ส่วน/แผนก บ่อยครั้ง โดยที่สิทธิ์ต้องไม่อัปเดตช้าหรือหลุด
* **การออกแบบระบบ:**
  * เชื่อมต่อกับ **Active Directory (LDAP)** ของโรงพยาบาลในการยืนยันตัวตน
  * เชื่อมโยงซิงค์กับฐานข้อมูลบุคลากร **Biosoft (HR MSSQL)** เพื่อดึงรายชื่อ, ฝ่าย, แผนก, ตำแหน่ง มาอัปเดตล่าสุดอัตโนมัติ
  * ระบบ **Dynamic Role Mapping** คำนวณสิทธิ์ให้พนักงานตามโครงสร้างองค์กรจริงทันที
  * สถาปัตยกรรมความปลอดภัย **Dual Token (JWT Access Token 15 นาที + Refresh Token Rotation)** และระบบ Token Blacklist
* **Tech Stack:** Frontend: **Next.js + Tailwind CSS** | Backend: **Rust (Axum) + PostgreSQL + MSSQL (Tiberius)**
* **🔗 GitHub Repository:** [https://github.com/vick42uho/yanhee_protal.git](https://github.com/vick42uho/yanhee_protal.git)

### 4. ระบบ Dynamic Icon Gate (Medical iFrame)
* **โจทย์จากผู้บริหาร:** **ได้รับ Requirement ตรงจากท่าน รอง ผอ.** ต้องการให้มีแถบไอคอนแสดงสถานะคนไข้เพิ่มเติมบนระบบ **Medhis (ระบบ HIS/EHR ของโรงพยาบาล)** โดยให้ทาง Medhis เจาะช่องเป็น iFrame แนวนอนเล็กๆ ไว้ให้
* **การออกแบบระบบ:**
  * พัฒนาระบบบริหารจัดการไอคอนขึ้นมา พร้อมทำ **API เชื่อมต่อไปดึงข้อมูลคนไข้จากฐานข้อมูลของ Medhis**
  * มี **Rule Evaluation Engine** คำนวณเงื่อนไขการแสดงผลแบบ Real-time เช่น:
    * ช่วงอายุ `0 - 15 ปี` แสดงไอคอนเด็ก
    * ช่วงอายุ `16 - 25 ปี` แสดงไอคอนเด็กโต
    * ช่วงอายุ `26 - 35 ปี` แสดงไอคอนวัยรุ่น
    * ตลอดจนเงื่อนไขแจ้งเตือนความเสี่ยงทางการแพทย์ ผลแล็บ และการแพ้ยา
  * **จุดเชื่อมโยงกับ AI-Focused:** โครงสร้างการคัดแยกคุณลักษณะคนไข้ (Feature Extraction) ในระบบนี้ คือรากฐานแบบเดียวกันกับการวาง **Data Pipeline สำหรับ AI Model** ในโรงพยาบาล
* **Tech Stack:** Frontend: **Next.js (iFrame Bar & Admin Dashboard)** | Backend: **Rust (Axum) + PostgreSQL JSONB**
* **🔗 GitHub Repository:** [https://github.com/vick42uho/iFrame.git](https://github.com/vick42uho/iFrame.git)

### 5. ระบบ TimeTrack OT (โมบายล์แอปบันทึกเวลาทำงาน & คำนวณโอที)
* **จุดเด่น:** แอปพลิเคชันบนมือถือสำหรับบันทึกเวลาทำงานและคำนวณ OT กะเช้า-กะดึกอัตโนมัติ พร้อมระบบแนบรูปถ่ายหน้าจอเครื่องสแกนนิ้วเป็นหลักฐาน
* **สถาปัตยกรรม:** ออกแบบเป็น **100% Offline-First** ใช้งานได้แม้ไม่มีสัญญาณอินเทอร์เน็ต ใช้ **Expo SQLite ในโหมด WAL (Write-Ahead Logging)** และเก็บไฟล์ภาพใน Sandboxed Storage
* **Tech Stack:** **React Native 0.81 + Expo SDK 54 + TypeScript**
* **🔗 GitHub Repository:** [https://github.com/vick42uho/TimeTrackOT.git](https://github.com/vick42uho/TimeTrackOT.git)
