## 🎙️ บทพูดแนะนำตัว & นำเสนอผลงาน (Master Presentation Script)

> **💡 คำแนะนำสำหรับการพูด:** นั่งหลังตรง สบตากรรมการทั้งสองท่าน (IT Manager & Head of HR) ด้วยน้ำเสียงเป็นธรรมชาติ มั่นใจ เป็นกันเอง ใช้เวลาพูดประมาณ 2-3 นาทีตามสคริปต์นี้ได้เลยครับ

"สวัสดีครับพี่ๆ ทั้งสองท่านครับ ผมชื่อ**วิค**นะครับ หรือชื่อจริง **ทวีป โปราหา** ครับ

ปัจจุบันผมเป็นโปรแกรมเมอร์อยู่ที่**โรงพยาบาลยันฮี**ครับ งานหลักๆ ที่ผมรับผิดชอบอยู่ที่ยันฮีตอนนี้ จะแบ่งเป็น **2 พาร์ทใหญ่ๆ** ครับ

### 🔹 พาร์ทแรก: งานดูแลและปรับปรุงระบบเดิมของโรงพยาบาล
พาร์ทนี้เป็นเว็บแอปพลิเคชันเดิมที่เขียนด้วยภาษา **PHP** ซึ่งตอนนี้ผมดูแลอยู่คนเดียวเกือบ 30 โปรแกรมเลยครับ  
ตัวหลักๆ ที่ผมได้เข้าไปปรับปรุง แก้ไข และเพิ่มฟังก์ชันใหม่ๆ ก็จะมีเช่น **Mini CRM**, **HOIR** (ระบบรายงานอุบัติการณ์และความเสี่ยง), **KPI**, และ**โปรแกรมอบรมบุคลากร**

ในพาร์ทนี้ กระบวนการทำงานของผมจะเป็นแบบ **End-to-End** เลยครับ คือ:

* **เริ่มจากการเข้าประชุมเก็บ Requirement:** นั่งคุยกับทั้ง ผอ., ผู้จัดการฝ่าย, และหัวหน้าแผนกต่างๆ ที่เกี่ยวข้อง เพื่อฟังว่าหน้างานเขาติดปัญหาอะไร หรืออยากได้ฟังก์ชันอะไรเพิ่ม
* **ลงมือพัฒนาและปรับปรุงระบบ:** เขียน PHP ปรับจูน SQL Query และเพิ่มฟีเจอร์ให้ตรงตามระเบียบปฏิบัติของโรงพยาบาลที่เปลี่ยนไป
* **จัดทำคู่มือและลงไปสอนใช้งาน (User Training):** ผมจะทำทั้งคู่มือการใช้งานทั่วไป และคู่มือการดึงรายงานสำหรับหัวหน้างาน พร้อมลงไปสอนพี่ๆ หน้างานด้วยตัวเอง
* **ดูแลและ Support ต่อเนื่อง:** คอยแก้บั๊ก และตอบคำถามผู้ใช้งานหน้างาน เพื่อให้ระบบรันได้อย่างราบรื่นครับ

### 🔹 พาร์ทที่สอง: งานออกแบบและสร้างระบบใหม่ (Full-Stack & Modern Architecture)
พาร์ทนี้จะเป็นการรับโจทย์ใหม่มา แล้วผมดูแลตั้งแต่การวิเคราะห์ Requirement, ออกแบบ Database, พัฒนาทั้ง Frontend และ Backend REST API จนถึงการ Deploy ขึ้น Production และเทรนนิ่งผู้ใช้งานครับ มีระบบสำคัญๆ 4 ตัวครับ:

#### 1. ระบบ IT Request (ระบบแจ้งซ่อมและของาน IT แบบ Paperless):
ระบบนี้ขึ้น Production ใช้งานจริงแล้ว ช่วยลดการใช้กระดาษและการโทรตามงานได้ 100%
* **Flow การทำงาน:** แยกประเภทใบคำร้องชัดเจน 3 แบบ คือ **งานบริการ, งานแก้ปัญหา, และงานพัฒนา** พอยื่นคำร้องมา ถ้าใบไหนต้องมีหัวหน้าอนุมัติ ระบบจะวิ่งตาม Flow ไปหา ผจก. หรือ ผอ. ก่อน
* พอจบฝั่งหน้างาน ฝั่ง IT เราจะมี Admin คอยคัดกรองเบื้องต้น แล้ว Assign จ่ายงานให้ทีมที่รับผิดชอบ แท็กชื่อคนทำงาน กำหนด Deadline พองานเสร็จ User จะเป็นคนตรวจรับและกดปิดงาน
* **Stack:** หน้าบ้านใช้ **Vite + React** หลังบ้านใช้ **FastAPI + PostgreSQL** ครับ

#### 2. ระบบ Patient Media (ระบบคลังภาพทางการแพทย์):
ตัวนี้ผมพัฒนาขึ้นมาใหม่เพื่อทดแทนโปรแกรมคลังภาพเดิมที่ไม่ตอบโจทย์แล้ว เน้นเรื่องการจัดเก็บภาพถ่ายการรักษาและแบบฟอร์มยินยอม (Consent) ของคนไข้ตามมาตรฐาน **PDPA** พัฒนาด้วย **React + FastAPI + uv + PostgreSQL** ครับ สถานะตอนนี้พัฒนาเสร็จแล้ว อยู่ในขั้นตอนเตรียมพูดคุยสรุป Flow หน้างานกับทีมเพื่อขึ้นใช้งานจริงครับ

#### 3. ระบบ Central Access Control (Yanhee IAM Portal):
ระบบนี้ผมได้รับ Requirement ตรงมาจากท่าน ผอ. เลยครับ ท่านอยากได้ระบบศูนย์รวมที่รวมทุกโปรแกรมในโรงพยาบาลไว้ที่เดียว ทำ Single Sign-On ล็อกอินครั้งเดียว แล้วจะมองเห็นเฉพาะโปรแกรมที่ตัวเองมีสิทธิ์ เข้าถึงได้ตามหมวดหมู่ชัดเจน  
และโจทย์สำคัญคือ เวลาโรงพยาบาลมีการปรับเปลี่ยนโครงสร้าง มีการโยกย้าย ฝ่าย ส่วน แผนก บ่อยๆ สิทธิ์จะต้องไม่หลุดหรือค้างเก่า ผมจึงออกแบบให้ระบบเชื่อมต่อกับ **Active Directory (LDAP)** เพื่อล็อกอิน และซิงค์กับฐานข้อมูล **Biosoft (HR)** เพื่อดึงรายชื่อ ฝ่าย แผนก ตำแหน่งมาอัปเดตล่าสุดอัตโนมัติ ทำให้หมดปัญหาสิทธิ์ไม่ตรงกับโครงสร้างจริงครับ

#### 4. ระบบ Dynamic Icon Gate (Medical iFrame):
ตัวนี้ผมได้รับ Requirement ตรงมาจากท่าน รอง ผอ. ครับ ท่านอยากได้แถบไอคอนแสดงสถานะคนไข้เพิ่มเติมบนระบบ Medhis (HIS เดิมของโรงพยาบาล) โดยให้ทาง Medhis เจาะช่องเป็น iFrame แนวนอนเล็กๆ ไว้ให้  
ผมจึงพัฒนาระบบนี้ขึ้นมา และทำ API เชื่อมต่อไปดึงข้อมูลจากฐานข้อมูลของ Medhis มาคำนวณเงื่อนไขการแสดงผลไอคอนแบบ Real-time เช่น ตรวจสอบช่วงอายุ 0-15 ปีให้ขึ้นไอคอนเด็ก, 16-25 เด็กโต, 26-35 วัยรุ่น รวมถึงเงื่อนไขความเสี่ยงทางการแพทย์ต่างๆ ครับ"
